# ADR-003: PyQt6 原生桌面界面与可选局域网 Web 服务的协同设计

## 状态
已接受 (Accepted) - 2026-11-01

## 背景
在视频下载与多媒体管理类应用中，通常存在两种开发路线：
1. **纯 Web 方案 (Electron / Web 前端 + 后端服务)**：
   - 依赖本地浏览器或 Chromium 进程，经常出现跨域、静态端口占用、浏览器弹窗被打断、以及 `Failed to fetch` 等断连报错；
   - 每次双击 exe 强制弹出外部浏览器，体验割裂，缺少原生桌面快捷键与托盘交互。
2. **纯桌面方案 (PyQt / WinForms)**：
   - 无法方便地将已下载视频流式推送到局域网设备（如移动端 iPhone / iPad 或家庭电视）进行同步观看与扫码下载。

## 决策
1. **以 PyQt6 原生 Win11 Fluent 架构为核心主入口**：
   - 默认直接启动原生桌面窗口（`desktop_app.py`），支持系统原生事件循环、全局热键注册（Win32 `RegisterHotKey`）、剪贴板哨兵、动态托盘环形进度绘制以及 Win32 原生资源管理器文件高亮选中；
   - 零网络请求开销，规避所有跨域与浏览器断联导致的 `Failed to fetch`。
2. **嵌入式可选 FastAPI 局域网服务 (`core/web_server_manager.py`)**：
   - Web 服务默认保持关闭，避免无谓占用系统端口；
   - 用户在需要多屏播放墙或 iPhone 扫码观看时，可点击一键按需开启；
   - 采用线程安全的事件总线与 SQLite WAL 模式，确保桌面端 GUI 与移动端 Web 共享同一个下载调度器状态。

## 后果
- **优势**：
  - 兼具原生桌面软件的极速响应、深度操作系统级控制与跨设备移动互联的灵活性；
  - 软件不会无故向系统浏览器弹出干扰标签页。
- **代价**：
  - 需同时维护桌面 Qt 控件逻辑与网页版轻量 HTML5 播放器。
